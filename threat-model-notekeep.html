Threat Model & Secure Hardening Plan

System: NoteKeep, a small web app where users register, log in, write private notes and attach files.

Method: Data-flow diagram + STRIDE, risks ranked by Likelihood × Impact (1–5 each). Prepared by: [Your Name] · Cyber Security Internship, Task 02

1. Scope & Assets

Assets: user credentials, session tokens, private notes, uploaded files, database, application secrets (DB password, JWT/session key), server availability.
Actors: legitimate user, attacker on the internet, malicious logged-in user, admin.
Assumptions: Node.js/Express app, PostgreSQL, object/file storage, third-party email service for password resets, hosted behind HTTPS.

2. Data-Flow Diagram with Trust Boundaries

Flows: 1 login/notes requests · 2 proxied requests · 3 file upload · 4 queries · 5 file write/read · 6 password-reset email.

6. Summary

The highest risks come from weak authentication, missing authorization checks, injection, and exposed secrets. Fixing the P1 items removes the most likely and most damaging attack paths. The remaining items add defense in depth. Residual risk will be reviewed after implementation.
